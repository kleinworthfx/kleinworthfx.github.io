Backlog

User stories

What the team is building, written from the user’s point of view.

US-01 · STUDENT
As a student, I want to paste a comment and instantly see whether its mood is positive, negative or neutral, so that I do not have to re-read feedback twice.
Acceptance criteria
  • Result appears without leaving the page.
  • Mood is labelled with a confidence score.
US-02 · SMALL BUSINESS OWNER
As a small business owner, I want a confidence score with each result, so that I know how much to trust the reading.
Acceptance criteria
  • Score shown as a percentage.
  • Low-signal comments read as neutral.
US-03 · SOCIAL MEDIA USER
As a social media user, I want a mood summary of my saved comments, so that I can see the overall tone at a glance.
Acceptance criteria
  • Summary counts positive, negative and neutral comments.
  • Chart updates as new comments are saved.
US-04 · RETURNING USER
As a returning user, I want my past comments saved in a history, so that I can track results over time.
Acceptance criteria
  • Each saved entry shows its mood and score.
  • History is stored in a database.
US-05 · FIRST-TIME USER
As a first-time user, I want a simple, easy-to-use interface, so that I can use the app without training.
Acceptance criteria
  • One clear input and one clear result.
  • No more than three steps to a result.

Section B · Reflection

Project reflections

STAR reflections on key parts of the Sentiment Mood Detector project.

Running the sprints

Situation
Two sprints across eight project weeks, with four members balancing other modules, meant tasks slipped early and stand-ups drifted.
Task
Get the sprint rhythm working so the board reflected actual progress.
Action
We tightened stand-ups to three questions, moved unfinished cards back to the backlog and re-prioritised work at the start of each week.
Result
By sprint 2, the board better reflected progress and the retrospective could focus on improvement.

Designing the comment experience

Situation
Early wireframes placed the input form, result and history on one dense screen, and testers hesitated about what to do first.
Task
Design a flow a first-time user could complete without instructions.
Action
I reduced the flow to type a comment, see the mood and confidence, then browse history; I used plain-language labels and tested the flow with classmates.
Result
The three-step pattern became the structure of the screens I built.

Testing the detector

Situation
The first version misread short comments and missed flipped meanings such as “not good”.
Task
Make mood labels trustworthy enough to show with a confidence score.
Action
We tested positive, negative, neutral and mixed comments, handled negation and intensifiers in the logic, and recorded wrong results for re-checking.
Result
Labels became more stable on the test set, and the confidence estimate helped communicate uncertainty.
