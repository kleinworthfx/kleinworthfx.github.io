Evidence area 2

User Stories

Eight candidate stories have been drafted from the supplied PayTrader source archive. They are not proof of eight team-approved or completed stories.

US-01

Trader registration

As an informal trader, I want to register an account so that I can use the platform.

Acceptance focus: required fields, duplicate email handling, password hashing and recorded test result.

US-02

Trader sign-in

As a registered trader, I want to sign in so that I can access my account.

Acceptance focus: valid/invalid credentials, token creation and protected-route behaviour.

US-03

Trader ID and QR code

As a trader, I want a unique trader ID and QR code so customers can identify my profile.

Acceptance focus: generation, dashboard display and real-device scan behaviour.

US-04

Simulated customer payment

As a customer, I want to identify a trader and enter an amount to experience the proposed flow.

Acceptance focus: valid trader, positive amount, reference and clear simulation disclosure.

US-05

Sales summary

As a trader, I want to see recorded sales summaries so I can review prototype activity.

Acceptance focus: totals compared with test records and clear payment-status treatment.

US-06

Transaction history

As a trader, I want to review my transaction records so I can check recorded activity.

Acceptance focus: own-account access, ordering, search and empty/populated history.

US-07

Profile management

As a trader, I want to update supported profile details so my information stays current.

Acceptance focus: valid updates, account association and persistence after reload.

US-08

Admin overview

As an administrator, I want to inspect trader and payment records to monitor prototype activity.

Acceptance focus: admin-only access, safe responses and totals checked against test data.

Each detailed story includes proposed acceptance criteria, candidate tasks, source files and fields for the actual Trello card, owner, estimate, status and test result.

Individual learning

My Reflections

Reflection connects an artefact to a specific experience, personal contribution, outcome and lesson. These prompts are not presented as completed personal accounts.

Team Charter · STAR

Situation: What real team situation made an agreement important?

Task: What were you personally responsible for?

Action: What did you personally do? Name the actual discussion or agreement.

Result: What changed and what evidence supports it?

Stories and Backlog · STAR

Situation: Which real user need did the team address?

Task: What story, task or priority decision did you contribute to?

Action: How did you clarify criteria or verify it?

Result: What happened and what did you learn?

Sprint and Logbook · STAR

Situation: Describe a real sprint activity, delay or dependency.

Task: What work were you expected to complete?

Action: What did you do and how did you communicate progress?

Result: What happened and what would you change?

Application · Technical reflection

Situation: Which application component did you personally work on?

Task: What user requirement did it address?

Action: Describe your actual research, coding, review or testing.

Application evidence

PayTrader Prototype

The supplied source archive contains a browser-based frontend and a Node.js/Express backend. Source review does not independently prove the application was run or tested.

Frontend

HTML, CSS, vanilla JavaScript, Bootstrap 5 and Font Awesome.

Backend

Node.js and Express with separate route/controller modules.

Data and security

JSON-file persistence, JWT authentication and bcryptjs password hashing in supplied source.

Important payment limitation

The supplied payment controller explicitly describes the flow as simulated: no real money moves. Real gateway integration, camera-based QR scanning, notifications and bank settlement are listed as future improvements.
