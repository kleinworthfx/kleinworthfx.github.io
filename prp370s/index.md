# PRP370S Portfolio of Evidence

**Project:** CampusConnect Marketplace  
**Assessment:** PRP370S Project Presentation 3 — October 2026  
**Submission deadline:** 27 October 2026  
**Status:** Draft evidence pack — factual verification required

## Purpose

This section organises evidence for the five categories in the assessment brief. It is based on the available CampusConnect Project 3 documentation and project proposal. It distinguishes documented project requirements from proposed Agile planning and from historical facts that still need confirmation.

The assessment brief asks for an e-portfolio that collects, selects, reflects on and connects evidence. Each of the five categories is assessed for evidence and reflection, worth 10 marks each.

## Assessment artefacts

1. [Agile Team Charter](team-charter.md) — purpose, team roster, working agreements and decisions requiring confirmation.
2. [User Stories and Tasks](user-stories.md) — user-centred stories, acceptance criteria and task breakdowns.
3. [Product Backlog](product-backlog.md) — proposed priorities and rationale.
4. [Sprint Backlog](sprint-backlog.md) — sprint goal, selected work, status and completion criteria.
5. [Agile Logbook](agile-logbook.md) — dated records, blockers, decisions and retrospective template.

## Project context from available documentation

CampusConnect is described in the project documentation as a university-focused, browser-based marketplace intended to help users discover and trade academic items. Documented requirement areas include university email access, listings, search and filtering, buyer–seller messaging, reviews, administration/moderation and approved collection points.

The documentation also states that integrated payment gateways and native Android/iOS applications are outside the initial documented scope. The final backlog should be checked against the team's current approved scope before submission.

## How to use this section

- Replace every **[CONFIRM]** or **[ADD]** marker with verified information.
- Keep proposed work labelled as proposed until the team actually agrees to it.
- Add genuine screenshots or links to the Trello board where available. Do not include private credentials, tokens or sensitive personal information.
- Write personal reflections in the first person and only describe experiences you can explain and support.
- If an event, date, estimate or outcome cannot be verified, state that the record is unavailable rather than inventing it.
